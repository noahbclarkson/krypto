### 3. The Equity Visualization Bug Makes Turtle Look Terrible

The progress chart's Turtle equity shows a "square wave" pattern hitting -100% repeatedly. This is NOT the real strategy behavior. The live paper mode shows BTC +102.6%, ETH +162.8%.

Root cause: `simulate_turtle_chandelier_equity()` in `progress_equity_curves.rs` writes equity only at trade exit bars. Between exit and next entry, equity is stored as 1.0 (not the actual equity value). When computing Sharpe from daily returns, bars at 1.0 with no trades create massive drawdown spikes.

The fix was documented (forward-fill equity) but the chart PNG was never regenerated from the corrected CSV.

**This makes Turtle look catastrophically worse than it actually is.** The visual misleads Noah into thinking the strategy has severe blowups.

## TOP 3 UNBUILT IDEAS

### 1. Turtle Self-Regime Monitor (no API keys needed)
- **Concept:** Use Turtle's own performance metrics as regime classifier. Track:
  - Rolling 60-day Sharpe of Turtle returns
  - Average Chandelier exit distance (in ATR units) over last 21 days
  - % of positions closed by Turtle ATR (vs Chandelier) — high % = chop
- **Decision rule:** If rolling Sharpe < 0 AND Chandelier exit distance > 2× ATR → reduce to CAP=2 or skip new entries
- **Why it might work:** Uses actual Turtle behavior, not external indicators. When markets are choppy, Turtle's own signals show degradation before losses compound.
- **Test:** Build `turtle_regime_monitor.rs` using backtest data only. No API keys needed. Run walk-forward with regime-adjusted vs fixed position cap.

### 2. SOL/USDT Microstructure Research
- **Concept:** We know SOL slippage at $100K = 3.7× model (3.70bp vs 1bp assumption). But we haven't studied WHY. 
- **Research question:** What is the typical bid-ask spread, order book depth, and microstructure of SOL-USDT at different times of day?
- **Could reveal:** (a) SOL is only tradeable at small position sizes, (b) there's a specific time-of-day edge, (c) the exchange's SOL liquidity is structurally thin
- **No API keys needed for research.** Can study historical spread data from our parquet files (volume, range as proxy).

### 3. In-Sample Overfitting Audit (the Monte Carlo we never ran)
- **Concept:** CTREND's 1438x might be overfitted to the specific price patterns in our data. Run a Monte Carlo permutation test: shuffle daily returns within each year, re-run CTREND, see if it still gets 1000x+.
- **Why:** We've been burned before by BollingerReversion's +5404 DOGE Sharpe that turned out to be look-ahead contamination. A Monte Carlo would tell us if CTREND's performance is robust or a mirage.
- **This is the honest version of entry 19.** Entry 19 said "run walk-forward" — but the real test is Monte Carlo permutation, not walk-forward (walk-forward tests temporal stability, Monte Carlo tests overfitting).
