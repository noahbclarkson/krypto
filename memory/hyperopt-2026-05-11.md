## Step 1: Audit Hardcoded Parameter

**Parameter:** `FRESHNESS_COOLDOWN` in `src/live/bot.rs`

**What it does:** Bars to wait after a position exit before re-entering the same symbol. Prevents whipsaw re-entries in choppy regimes where a stop fires and the same symbol immediately retriggers an entry.

**Current hardcoded value:** `0` (disabled)
**Production default:** not set — always disabled

**Why this matters:** FC=0 allows immediate re-entry after a stop loss, which in volatile choppy regimes causes rapid consecutive losses. The ATR_RANK gate (T=5) already filters regime quality but doesn't prevent rapid re-entry within the same high-vol regime.

## Conclusion

**FRESHNESS_COOLDOWN = 93 is promoted to production.**

This is the first entry-timing parameter validated on the exact-live path (vs the prior TURTLE_ATR_PERIOD which was inert). The 93-bar (~3 month) cooldown prevents whipsaw re-entries and dramatically improves walk-forward robustness: +31 pp pass rate, +1.77 Sharpe, -35 pp MaxDD vs FC=0 baseline.

**Trade-off:** Lower raw equity on the full history run (1.69x vs 3.01x for FC=0) because the cooldown prevents some winning re-entries. But walk-forward pass rate (83% vs 52%) is the correct production metric — we want a strategy that works across regimes, not one that overfits to the specific history.

**Note on exact-live vs research harness gap:** The equity curves (FC=93 at 1.69x vs FC=0 at 3.01x on Base5 full run) are from the same exact-live harness, so they're internally consistent. The "lower equity" result is real — FC=0 captures more raw return through more trades, but at the cost of much higher drawdown (58.7% vs 23.5%) and lower robustness. For production, we choose the robust parameter.
