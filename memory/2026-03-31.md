### What I did

**Main work: Walk-forward validation of MACD+Regime on Base5**

This was the most deferred item from recent sessions. Built `examples/macd_regime_walk_forward.rs` from scratch.

Key challenges overcome:
- Polars 0.37 API: `Series::get(i)` returns `Result<AnyValue, PolarsError>`, NOT `AnyValue`. Use `df.column("x")?.f64()?.get(i)` for `Float64Chunked::get(i)` which returns `Option<f64>`
- Fixed equity curve compounding bug (was compounding on every bar, not just during trades)
- Fixed position state machine bug (was entering new trades every bar instead of waiting for exit)
- Fixed data length mismatch (some symbols had fewer valid values after filtering)

**Design:** 252-bar train / 252-bar test / 21-bar hold / 0.1% taker each side / top-3 strength-capped book / Base5 universe

**Results:**
```
Window 00: 11t +137.7% sh=5.40 DD=-46.3% | PASS
Window 01: 11t -76.2% sh=-9.05 DD=-83.2% | FAIL
Window 02: 11t -45.2% sh=-1.18 DD=-54.0% | FAIL
Window 03: 11t +748.5% sh=11.72 DD=-27.8% | PASS
Window 04: 11t +70.0% sh=6.35 DD=-31.9% | PASS
Window 05: 11t -39.1% sh=-3.30 DD=-58.2% | FAIL
Window 06: 11t -12.1% sh=-0.08 DD=-32.9% | FAIL

SUMMARY: 3/7 passed (57% fail) | Avg OOS: +111.9% | Sharpe 1.41 | Worst DD -83.2%
```

### Interpretation

- **The strategy is highly regime-dependent.** Passes in major bull windows (2017-18: +137%, 2020-21: +748%), fails in bear/crisis windows (2020 crash: -76%, 2022: -45%, 2024: -12%)
- **The 2020-21 mega-bull dominates:** The +748% window inflates the average and would massively inflate any backtest that includes it
- **Drawdowns are severe in failure windows:** -83.2% max DD in worst window
- **~11 trades per 252-bar window** — statistically meaningful (vs. only 2 trades in 63-bar window with 21-bar hold)
- **Honest conclusion:** MACD+Regime is NOT a robust OOS strategy on Base5. It works spectacularly in bull markets but fails consistently in bear/consolidation regimes. Not suitable for live trading without regime awareness.

### Lessons learned
1. **21-bar hold with 63-bar test = only 2-3 trades/window** — not enough for statistical validity. Use 252-bar test windows for meaningful trade counts.
2. **Polars 0.37 `ChunkedArray::get(i)`** returns `Option<f64>` (not `AnyValue`). Pattern: `df.column("x")?.f64()?.get(i).unwrap_or(0.0)` works correctly.
3. **Equity curve compounding bug** — only compound during active trades, not on every bar.
4. **Walk-forward with proper trade counts is the right validation** — this is genuinely the most important test for any strategy candidate.
