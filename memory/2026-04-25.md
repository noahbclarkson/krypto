## Brutal Critique of Current Project State

### 1. T3 (EP Held-Out Validation) Is NOT Complete

**What the commit claims:** EP=24 confirmed vs EP=21 on pre-2021 data
**What was actually run:** `regime_stress_p7_validation.rs` tests P=7/M=2.25 (NOT current P=7/M=2.30) on pre-2021 data. The paired comparison (EP=21 vs EP=24 using current production params on held-out data) described in the PLAN.md T3 section was either not run or not completed.

**The gap:** Production params (EP=24, CHAND_P=7, CHAND_M=2.30, HM=12, ATR_ENTRY_MULT=0.00) have never been tested in a paired held-out comparison against EP=21. The M=2.25 stress test used different params than current production. We don't know if EP=24 is real on current params.

**Why this matters:** EP=24 won by +2 windows over EP=21 in the 54-window OOS test. At a 30% false-positive rate per window at the 70% threshold: expected ~3 false winners per 96-value sweep. A 2-window delta is noise-level.

**What needs to be done:** Run `regime_stress_paired.rs` (or equivalent) comparing EP=21 vs EP=24 on current production params (P=7, M=2.30, HM=12) against pre-2021 held-out data. This was the T3 deliverable. It is still not done.

### 2. T6 (CTREND Fixed-Hold) — "Complete" Is Overstating the Result

**What the commit claims:** VIABLE signal family (44/60 pass), win condition met
**What it means:** CTREND fixed-hold (10-90 bar hold periods) = 44/60 pass rate. CTREND + Chandelier (original test) = 30/54 pass rate. Fixed hold is genuinely better than Chandelier exit for CTREND signal. The signal IS real (confirmed by Monte Carlo).

**The problem:** 44/60 = 73% pass rate is BELOW Turtle+Chandelier's 80%+ pass rate. CTREND fixed-hold is a secondary signal, not a replacement. The "complete" framing obscures that it's a weaker signal that doesn't beat Turtle — it just means CTREND isn't dead.

**What should be documented:** "CTREND fixed-hold is a genuinely different signal family (not just Turtle parameter tuning). It is VIABLE as a secondary sleeve but NOT as a standalone replacement for Turtle+Chandelier. Expected role: 20-30% portfolio sleeve with different market regime sensitivity."

### 3. The ATR_ENTRY_MULT Revert Shows We Still Don't Have Proactive Anti-Overfitting Discipline

The sequence:
- 2026-04-21: EP=24 + ATR_ENTRY_MULT=0.85 both optimized on the same OOS data
- 2026-04-25 AM: Both claimed as winners simultaneously (sequential optimization on same data)
- 2026-04-25 PM: ATR_ENTRY_MULT=0.85 reverted to 0.00 (anti-overfitting discipline applied)
- 2026-04-25 PM: EP=24 was NOT reverted despite also being optimized on the same data

The anti-overfitting discipline was applied selectively — to the parameter that happened to fail, not to the principle itself. The same data was used to optimize EP=24 and then to claim EP=24 was valid. No held-out was run.

**The rule should have been:** If two parameters are optimized on the same OOS data and neither has been held-out tested, both must be held-out tested before being accepted. EP=24 has not been held-out tested on current production params. It should be reverted to EP=21 until that test is run.

### 5. The Anti-Overfitting Rules Are Written But Not Consistently Applied

The rules say:
- "Minimum win margin: ≥3 windows (5.5%) on OOS before accepting param change"
- "No sequential optimization on same data"
- "Held-out validation required for marginal wins (1-2 window delta)"

EP=24 violates rule 3: it's a 2-window margin improvement on OOS, has never been held-out tested on current params, and was optimized on the same data as ATR_ENTRY_MULT (which was subsequently rejected for exactly this reason).

The anti-overfitting discipline was applied to ATR_ENTRY_MULT but not to EP=24, even though both were optimized on the same data in the same session.

Turtle+Chandelier is the ONLY validated strategy. Every other idea has been killed. If Turtle+Chandelier has a hidden failure mode (e.g., regime where dual-exit collapses, or structural change in crypto microstructure after 2021), the entire project fails simultaneously.
