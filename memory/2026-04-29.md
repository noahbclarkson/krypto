### 2. Equity Bug: STILL PRESENT (Despite Commit Claim)

**What the commit says:** "equity bug fixed"
**What actually happened:** Only docs and binary parquet files changed. Zero Rust source lines modified.

**Evidence:**
```
src/live/config.rs:         — no change in this commit
examples/progress_equity_curves.rs: — no change in this commit
```
The parquet caches were refreshed (tiny binary diffs), so the harness now produces 221.5x instead of 1.0x. But the underlying harness off-by-one bug is still present:

```
Row 2086: turtle_equity = 1.000000   ← WRONG (off-by-one forward-fill)
Row 2087: turtle_equity = 221.496697 ← CORRECT (cargo run output says 2087 days)
```

The harness still shows 1.0x at row 2086 then 221.5x at row 2087. The final value is correct by coincidence (two rows of data), but the off-by-one bug in the forward-fill logic is unfixed.

**Why this keeps being misreported:** The harness completes successfully and produces the correct final equity value. The bug only manifests as a wrong intermediate value. It's easy to miss. But claiming "fixed" when no code changed is dishonest.

**Fix:** The bug is in the equity recording loop in `progress_equity_curves.rs`. The loop exits when `bar >= total`, but the last position's exit isn't recorded before the loop exits. Then the forward-fill fills row 2086 (bar=total) with the wrong value. One targeted edit fixes this.

### 3. Metrics Integrity: Two Numbers, One Source of Truth

**The two numbers are not directly comparable.** Walk-forward Sharpe averages per-window Sharpe ratios. Daily equity Sharpe is from one long compounded series. A strategy that makes +10% every window and one that makes +50% in half and -30% in half could have similar per-window Sharpe but very different equity Sharpe.

**What matters:** The equity Sharpe (~1.29-1.94 depending on data period) is what you'd actually experience. The walk-forward Sharpe is a robustness measure.
