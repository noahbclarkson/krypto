# Hyperopt Report — 2026-04-29 — VOL_LOOKBACK Production Re-validation

## Target

**Parameter:** `VOL_LOOKBACK` — rolling volume smoothing window used by the walk-forward validation harness for dollar-volume ranking / top-N symbol selection.

**Why this parameter:** It is hardcoded in the validated Turtle+Chandelier walk-forward harness and materially affects which symbols enter the portfolio. It is harness-only (not live bot execution), but it controls reported validated results. Earlier dense sweep evidence was stale/mixed; this re-run matches the current production validation logic exactly.

## Audit finding

Current validated strategy constants:
- `EP=21`
- `CHAND_PERIOD=7`
- `CHAND_MULT=2.30`
- `TURTLE_ATR_PERIOD=24`
- `TURTLE_ATR_MULT=2.00`
- `HOLD_MAX=12`
- `POSITION_CAP=3`
- `ATR_ENTRY_MULT=0.00`
- `VOL_LOOKBACK=8` (harness-only)

Important correction during implementation: a first draft of the new sweep harness used a stricter entry-fee convention and the wrong Turtle ATR trail direction. I caught this by comparing against `turtle_chandelier_walkforward.rs`, corrected it, and re-ran so the sweep now matches the validated harness output exactly.

## Sweep design

- **Range:** `VOL_LOOKBACK = 1..=100`, step 1 (**100 values**, full logical integer range)
- **Validation:** 9 universes × 6 walk-forward windows = 54 OOS windows per value
- **Data:** 2088 aligned daily bars, 252 train / 252 test windows
- **Selection rule:** robustness first — pass count, then positive universes, then avg Sharpe, then avg return. Did **not** choose by raw return alone.
- **Outputs:**
  - Metrics: `krypto/snapshots/vol_lookback_prod_sweep.csv`
  - Summary: `krypto/snapshots/vol_lookback_prod_summary.csv`
  - Equity time series: `krypto/snapshots/vol_lookback_prod_equity.csv`
  - Chart: `krypto/charts/comparison_chart.png`
  - Harness: `krypto/examples/vol_lookback_prod_sweep.rs`
  - Plot script: `krypto/charts/plot_vol_lookback_prod.py`

**No default change.** `VOL_LOOKBACK=8` remains the stable harness default.

# Hyperopt Addendum — ATR_ENTRY_MULT Current-Params Sweep

## Target

**Parameter:** `ATR_ENTRY_MULT` — hardcoded Turtle breakout ATR confirmation filter.

**Why this parameter:** It is used in the validated Turtle+Chandelier family, but prior EM sweeps were mixed/stale against older `CHAND_PERIOD=11`, `CHAND_MULT=2.25`, or `EP=24` configurations. Current production is `EP=21`, `CHAND_PERIOD=7`, `CHAND_MULT=2.30`, `HOLD_MAX=12`, `POSITION_CAP=3`, `VOL_LOOKBACK=8`, so the assumption needed direct re-test.

## Sweep design

- **Range:** `ATR_ENTRY_MULT = 0.00..=2.00`, step `0.01` (**201 values**)
- **Validation:** 9 universes × 6 walk-forward windows = 54 OOS windows per value
- **Total:** 10,854 window-runs
- **Selection rule:** robustness first — pass count, then avg Sharpe/return. Did **not** pick max raw return.
- **Outputs:**
  - Harness: `krypto/examples/atr_entry_mult_current_sweep.rs`
  - Metrics: `krypto/snapshots/atr_entry_mult_current_sweep.csv`
  - Summary: `krypto/snapshots/atr_entry_mult_current_summary.csv`
  - Equity time series: `krypto/snapshots/atr_entry_mult_current_equity.csv`
  - Plot script: `krypto/charts/plot_atr_entry_mult_current.py`
  - Chart: `krypto/charts/comparison_chart.png` (also saved as `atr_entry_mult_current_comparison.png`)

## Result

**Candidate winner: `ATR_ENTRY_MULT=0.94` — but NOT promoted yet.**

Top robustness results:

| EM | Pass | Avg Sharpe | Avg Return | Avg DD | Trades |
|---:|---:|---:|---:|---:|---:|
| 0.94 | **42/54 (77.8%)** | 5.3447 | +73.0% | 28.3% | 486 |
| 1.07 | 41/54 (75.9%) | **7.8590** | +91.9% | 24.8% | 428 |
| 1.08 | 41/54 (75.9%) | 7.8423 | +91.7% | 24.8% | 427 |
| 0.91 | 41/54 (75.9%) | 5.2687 | +74.2% | 28.3% | 490 |
| 0.88 | 41/54 (75.9%) | 5.2058 | +75.5% | 28.6% | 497 |
| 0.00 baseline | 40/54 (74.1%) | 3.1471 | +105.3% | 35.4% | 721 |

High EM values above ~1.5 produce unstable/inflated Sharpe due near-zero return variance and are rejected despite occasional high reported Sharpe.

## Interpretation

`ATR_ENTRY_MULT` has a real interaction with `CHAND_PERIOD`. Under current tight `CHAND_PERIOD=7`, non-zero EM around `0.88..0.94` improves robustness versus EM=0.00 by blocking weak breakouts that quickly get stopped out by the tight Chandelier exit.

However, this value was selected from the same 54-window WF grid used for evaluation. Following anti-overfit rules, I **did not update production defaults**. `ATR_ENTRY_MULT=0.00` remains the stable production default until a held-out confirmation test validates EM=0.94.

## Verification

Ran authoritative harness after the sweep:

```bash
cargo run --example turtle_chandelier_walkforward --profile sweep
```

Current defaults still pass known validation:
- Global pass: **40/54**
- Base5 pass: **6/6**
- Avg Sharpe: **3.1471431966**
- Total trades: **721**

## Decision

**No default change yet.** New candidate discovered (`ATR_ENTRY_MULT=0.94`), but it needs held-out validation before promotion.

Next validation gate: pre-2021 held-out / paired validation comparing `EM=0.00` vs `EM=0.94` under current `CHAND(7,2.30)/EP=21` params.
