## Biggest Blind Spots

### 1. We're only testing in simulated/execution-missing conditions
All validation is historical backtest. We have NO live market microstructure data. The maker-fill rate, slippage, order execution latency, and WebSocket bar quality are all assumed. 2026 YTD -22.7% in a BTC+12.7% market means the strategy's live signal quality in current conditions is unknown.

### 2. We keep re-optimizing the same strategy
Turtle+Chandelier has been hyperopted for 10+ parameters across 3 weeks. Every session adds another sweep. The marginal discovery value of the 11th parameter sweep is near zero. The strategy is either production-worthy or it's not — live testnet answers that.

### 3. P=15/M=1.50 is unconfirmed as production improvement
7/9 universe validation ≠ 9/9. The 2 failures (LTC/EOS/BCH) are structural asset-class issues. The question was: does P=15/M=1.50 improve Base5/NoDOGE (the actual production universe)? The answer from the separate harness was 7/9 pass. That's 78% — above 75% threshold but marginal. We should not be treating this as confirmed production improvement without a full re-run.

### 4. We don't have a live P&L tracking system
The live bot exits are logged, but there's no live equity curve or real-time Sharpe estimation. We'll be running blind for 30 days.

### 5. The example file graveyard
20+ example files in `examples/` are stale, superseded, or single-use prototypes. `ddbudget_3sleeve_walkforward.rs`, `macd_regime_walkforward.rs`, `cross_market_equity_walkforward.rs`, etc. These create confusion for anyone reading the codebase and may confuse future maintainers (including future-us).
