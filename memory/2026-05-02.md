### CRITIQUE-2: VL=96 vs VL=8 Was a Waste of Compute

T37 result: **6/6 windows TIE, 0 delta**. VL=8 and VL=96 produce IDENTICAL results at T=24 ATR rank threshold.

**Why this happened:** The ATR rank filter (T=24) gates entry by BTC's volatility regime. Once you're filtering by vol regime, the smoothing window for the *dollar-volume ranking* is irrelevant — the vol filter already selects a regime where ranking is stable. The VL parameter only affects ranking when the vol gate is loose (T=0). At T=24, it's irrelevant.

**What this means:** We ran 72 simulations (6 symbols × 6 windows × 2 VL values) to confirm a null result. This is the definition of a confirmation spiral — VL=8 was already the default, we suspected VL=96 was an artifact, and we confirmed it with extra compute. We should have simply removed the VL=96 claim from config.rs comment and moved on.

**Anti-pattern:** When the same-harness artifact concern is strong (EP=24 pattern), the correct response is to NOT run the comparison at all on the same harness, or to use a held-out split. Running it again on the same harness and getting a tie doesn't prove artifact — it just confirms the null.

**The better move:** Base5-only held-out confirmation of VL=96 would have taken 5 minutes and given us an honest answer. The full 9-universe run was overkill for a claim we suspected was false.

### CRITIQUE-3: REGIME_ATR_PERIOD=64 Is a Suspicious Spike

REGIME_ATR_PERIOD=64 (AP=64) was promoted as a new default (from AP=12) based on an extensive sweep: `AP∈[5..=80 step 1] × 9 universes × 7 WF windows`. Result: AP=64 gets 55/63 pass (+2 vs AP=12 baseline), Sharpe 6.19 (+0.76 vs 5.43), DD -7.0pp.

**The problem:** AP=64 is described as "the sole peak — Sharpe drops sharply to AP=65 (3.07) and AP=63 (5.27)." A drop from 6.19 to 3.07 at AP=65 is an enormous cliff. This is characteristic of overfitting to a single window split or an artifact of the walk-forward granularity.

**What to check:** AP=64 means the regime detection uses a 64-bar ATR on a daily chart. That's ~10 weeks. The regime lookback is LB=42. Combined with ATR rank threshold T=24, the warmup period is 64+42+2 = 108 bars. For a strategy with HOLD_MAX=12, this means the ATR rank filter only becomes active after ~108 bars — a significant fraction of the test period.

**Anti-overfit concern:** Our guardrail says "minimum 3-window (5.5%) improvement before accepting param changes." The improvement here is +2 windows (52→54) and +0.76 Sharpe. This passes the threshold. But the mechanism (AP=64 hard cliff) is suspicious. 

**Recommendation:** Run a held-out validation of AP=64 vs AP=12 on pre-2026 data (an out-of-sample split that was never used in the AP sweep). If AP=64 wins on held-out, accept. If not, revert to AP=12 or a plateau like AP=39-42.

## Biggest Blind Spots

**1. We only know the strategy works in simulation.**
All walk-forward results are upper bounds. The live bot has been running for ~5 weeks but we have no feedback loop because testnet API keys are missing. We don't know:
- Actual maker fill rate in live trading (vs 70% assumption)
- Real execution slippage vs model
- Whether the ATR rank filter is too restrictive or too loose in live deployment
- Whether HOLD_MAX=12 + Turtle ATR exit produces the expected behavior

**2. The strategy has only been tested in a bull-era dataset (2017-2026).**
The per-year decomposition shows 2021 (+35.5%) and 2022 (+10.9%) as weak years — but both still positive. The strategy has never experienced a prolonged bear market like 2014-2015 (-80% BTC). We assume Chandelier protects in drawdowns, but the data doesn't show a full multi-year bear.

**3. We're over-trading in the backtest.**
Total trades in the progress harness: 397 for the full history. That's ~40 trades/year, ~3-4 symbols active at once. With POSITION_CAP=3 and ~6 candidate symbols, the portfolio is not over-concentrated. But in choppy regimes (2021, 2022), the strategy fires 8-10 trades that all lose small — the fee drag accumulates.

**4. We don't know if the vol regime signal is stable in live.**
The ATR rank uses 252-bar history for the percentile. This means the rank is stable and slow-moving. In live deployment, 252 bars = ~1 year of data. The rank will only shift gradually. But if BTC's vol profile changes structurally (e.g., ETF approvals reduce BTC vol permanently), T=24 might need re-tuning.
