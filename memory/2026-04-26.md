## Bugs Found and Fixed

**Critical data loading bug in S6 (first attempt):**
- Original walk-forward takes FIRST min_len rows per symbol (2017-08-17 to 2023-05-02 for BTC)
- S6 (first attempt) was taking LAST min_len rows (2020-08-11 to 2026-04-26 for BTC)
- This caused S6 to test on DIFFERENT data than the original walk-forward
- Result: 0 signals because BTC at bar 252 (2021-04-20, mid-bull) was below the max_21 from 2020-08 to 2021-04
- Fix: take FIRST n_min rows (same as original), not last

**Critical turtle_signal bug in S6 (first attempt):**
- My version used range `[bar+1-EP..=bar]` — includes the current bar in the max calculation
- Original uses range `[bar+1-EP..bar)` — excludes the current bar
- For bar 252: my max was over indices [232..=252], original was [232..252)
- In a bull run, including the current bar in max_21 gives a higher threshold (current bar is near the high)
- This caused ALL signals to fail (close ≤ max_21 because current bar IS the max)
- Fix: use the original range [start..idx) which excludes idx
