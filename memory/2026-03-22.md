### Intra-Bar Trailing Stop Validation (CRITICAL FINDING)

**Problem Identified**: Daily backtest assumes price went high → low (trailing benefits from high before checking stop). But with OHLC data, we don't know the actual sequence.

**Analysis Method**:
1. Built `intra_bar_sequence_analysis` to check high/low sequence in 30m data
2. Built `intra_bar_worst_case` to simulate pessimistic execution (low before high)
3. Built `intra_bar_realistic` to simulate conservative 30m execution

**High/Low Sequence Analysis (10,000 days)**:
- High before low: 50.98%
- Low before high: 49.02%

**The sequence is essentially a COIN FLIP.** The optimistic assumption is wrong ~49% of the time.

### Impact Quantification

| Symbol | Optimistic Return | Worst-Case Return | Realistic (30m) Return |
|--------|-------------------|-------------------|------------------------|
| BTCUSDT | +811% | -23% | -23% |
| ETHUSDT | +641% | -36% | -36% |
| SOLUSDT | +30,551% | -50% | -50% |

**THE ENTIRE EDGE EVAPORATES WITH REALISTIC EXECUTION.**

The strategy goes from highly profitable (+642-30744% returns) to LOSING MONEY (-23% to -50%) when using 30m intra-bar resolution with conservative stop checking.

### Root Cause

1. **Daily optimistic model**: Assumes high → low sequence, so trailing stop benefits from the day's high before checking if low hit the stop
2. **30m realistic model**: Checks stop BEFORE updating trailing within each 30m bar
3. **Result**: The "edge" was entirely from assuming favorable intra-bar sequence

### Why This Matters

The BollingerReversion strategy with ATR×0.3 stop was showing:
- 99-100% profitable with random entry (daily data)
- Sharpe ratios of 100-37,000 (daily data)

But with realistic execution (30m data), it becomes:
- **ALL LOSING** (-23% to -50% returns)
- Sharpe ratios of -4.3 to -4.7

**The edge is NOT robust.** It's an artifact of optimistic backtest execution.

### Implications

1. **HALL_OF_FAME entries are INVALID** — based on optimistic execution
2. **Live trading would LOSE MONEY** — not profitable with realistic fills
3. **All backtests need intra-bar validation** — daily OHLC is insufficient
4. **The "tight stop edge" is a backtest artifact** — doesn't survive realistic execution
