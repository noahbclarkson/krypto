# Hyperparameter / Assumption Audit — TAKER_FEE Effective-Cost Sweep
**Session:** 2026-04-30 09:44 UTC | Kira hyperopt cycle  
**Mission:** Audit hardcoded validated-strategy constants, export equity curves, run extensive grid sweep.

## Parameter Audit Finding

Chosen hardcoded assumption: `TAKER_FEE` in the validated Turtle+Chandelier walk-forward harness.

- Historical harness: `const TAKER_FEE: f64 = 0.001` = **10 bps/side**.
- Live config / paper harness: `fee_pct = 0.0004` = **4 bps/side**.
- More importantly, `examples/turtle_chandelier_walkforward.rs` applies the fee as:
  - entry = `entry_px * (1.0 - TAKER_FEE)`
  - exit = `exit_px * (1.0 - TAKER_FEE)`
  - return = `exit / entry - 1.0`

Because the same multiplier is used on both sides, the fee **cancels algebraically**. Re-running the authoritative harness confirms the reported 34/54 pass and avg Sharpe 3.392 are effectively **no-fee** metrics, despite the harness claiming `0.1% taker each side`.

## Harness + Charting Updates

Built `krypto/examples/fee_sweep_walkforward.rs`:
- Correct long-side cost accounting: entry = close × `(1 + fee)`, exit = close × `(1 - fee)`.
- Extensive sweep: **0..20 bps/side step 1 bp** = 21 fee levels.
- Validation: **9 universes × 6 windows = 54 OOS windows/fee**.
- Records return, Sharpe, max DD, trade count, win rate, and pass/fail.
- Exports Base5 OOS time-series equity curves for charting.

Built `krypto/charts/plot_fee_sweep.py`:
- Reads summary + equity CSVs.
- Plots line curves for no-fee upper bound, live 4 bps, historical 10 bps, and 15/20 bps stress cases.
- Uses dynamic log-scale Y-axis, labels, legend, title, and grid.
- Output chart: `krypto/charts/comparison_chart.png`.

Outputs:
- `krypto/snapshots/fee_sweep_walkforward_metrics.csv`
- `krypto/snapshots/fee_sweep_walkforward_summary.csv`
- `krypto/snapshots/fee_sweep_walkforward_equity.csv`
- `krypto/charts/comparison_chart.png`

## Results

| Fee/side | Pass | Avg Return | Avg Sharpe | Worst DD | Trades |
|---:|---:|---:|---:|---:|---:|
| 0 bps | 34/54 | +113.6% | 3.392 | 79.3% | 743 |
| 4 bps (live config) | 34/54 | +111.2% | 3.303 | 79.6% | 743 |
| 10 bps (historical hardcode, correctly applied) | 34/54 | +107.8% | 3.170 | 79.9% | 743 |
| 20 bps stress | 34/54 | +102.2% | 2.950 | 80.5% | 743 |

## Decision

No strategy hyperparameter default changed. Fee is an execution-cost assumption, not an optimizable trading knob.

But the validation harness has a real accounting flaw: its hardcoded `TAKER_FEE=0.001` does not actually penalize returns because entry and exit use the same `(1-fee)` multiplier. The good news: applying fees correctly does **not** change pass rate over 0..20 bps/side; the edge is robust to realistic fee levels. The bad news: historical reported returns/Sharpe are mildly overstated versus correct cost accounting.

Stable calibrated execution assumption remains **4 bps/side** in live config, but future walk-forward harnesses should use the corrected accounting formula.
